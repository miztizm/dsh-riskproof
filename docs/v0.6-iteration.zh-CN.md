## 从参考项目得到的改进

dsh-vault 的凭据模型包含 OAuth token、私钥和 TOTP 等字段，并将不含秘钥的搜索摘要
与完整凭据读取区分。对 RiskProof 的启发是：除了常见 token 格式，还需要识别普通
工具输出中的结构化凭据字段。v0.6 增加精确字段匹配，覆盖嵌套对象和数组，不依赖
工具名称或特定提供商前缀；可信降密工具返回的敏感值仍会重新获得标签。

dsh-permission-rules 提供规则试算、审计与配置验证。RiskProof 增加
`/riskproof test <tool> <JSON>`，让操作者在执行前查看本插件的真实规则结论。
试算复用当前会话的来源、任务范围和身份基线，不派发工具、不生成回执，不建立或
替换身份 pin，不写入真实调用使用的分类缓存，也不申请或绕过宿主审批。

## 安全边界与验证

不因工具名来自某个项目而建立信任或放行；vault 摘要工具仍受已有保守来源分类约束。
不引入 LLM 判定、通用规则 DSL 或凭据存储。字段识别无法覆盖改名、编码、拆分或
数字形式的所有秘钥。试算不检查其他插件和执行后输出，结论也不授权未来调用。

回归覆盖：嵌套 OAuth/TOTP/私钥、摘要字段误报、可信降密后的重新标记、试算与
当前来源链、任务范围、会话隔离、身份基线连续性、容量不变、错误脱敏和双语输出。
真实 DSH 安装夹具增加不执行的规则试算、计数不变及普通工具返回 opaque OAuth
token 时的输出拦截。完整发布验证仍执行项目既有的本地检查和远端兼容性矩阵。

使用说明见 [执行前试算](policy-preview.md)。

并在 Chrome 156 的中文、英文桌面及 390px 窄屏通过 Web 验收。
